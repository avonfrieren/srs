# srs — Contexte & architecture

Mod Everest **compagnon** de [DemoJameson/Celeste.SpeedrunTool](https://github.com/DemoJameson/Celeste.SpeedrunTool) (MIT), frère de `srta` (même philosophie : dépendance + hooks, jamais de fork). But : importer la practice sheet communautaire (Google Sheets → CSV local) et colorer le temps final d'un segment du room timer selon les paliers de la sheet.
Roadmap dans `PLAN.md`. Le `README.md` sert de **changelog + instructions d'installation** — le mettre à jour à chaque feature.

## Build

- .NET 8 (`net8.0`), projet unique `srs.csproj`. Sur cette machine : `~/.dotnet/dotnet build -p:CelestePrefix="$HOME/.steam/steam/steamapps/common/Celeste"`.
- Références jeu résolues via `CelestePrefix` (auto-détecté si le repo est cloné dans `<Celeste>/Mods/xxx/`).
- **`SpeedrunTool.dll` extraite automatiquement du `SpeedrunTool.zip` officiel installé** (cible `ExtractSpeedrunToolDll`), épinglé sur **v3.27.17** dans `everest.yaml`. Pas de Publicizer pour l'instant (rien d'interne utilisé) — à ajouter comme dans srta si la phase 4 l'exige.
- Cible `OutputAsModStructure` : génère `build/` (DLL + PDB + `everest.yaml` + `Dialog/`) → à zipper en `srs.zip` dans `<Celeste>/Mods/` (comme `srta.zip`) ou copier en dossier `Mods/srs/`.
- `srs.csproj` contient `<Compile Remove="Tests/**" />` : **ne pas retirer** — le SDK globbe `**/*.cs`, sans ça les sources de test (et les fichiers générés de `Tests/obj/`) partiraient dans `srs.dll`.

## Tests

- `Tests/srs.Tests.csproj` (xUnit, net8.0). Lancement : `cd Tests && ~/.dotnet/dotnet test`. **Aucune référence à Celeste/SpeedrunTool** : le projet `<Compile Include>` directement les fichiers source game-free (`SheetData.cs`, `SegmentAutoDetect.Names.cs`) au lieu de référencer `srs.dll` — donc les membres `internal` (`Csv`, `Import`, `ParseBlocks`, `CheckpointMap`, `CategoryVariants`, `GameNameOf`) sont visibles depuis les tests sans `InternalsVisibleTo`. Corollaire : garder ces fichiers-là sans `using` du jeu (d'où la découpe `SegmentAutoDetect.Names.cs`, qui isole la partie qui touche SpeedrunTool/Celeste).
- `Tests/SheetConsistencyTests.cs` — **le plus important** : croise les trois tables hardcodées (`SheetData.Import`, `SegmentAutoDetect.CheckpointMap`, `SegmentAutoDetect.CategoryVariants`) entre elles et avec les CSV réels. C'est ce qui rend visible la panne silencieuse typique — un renommage côté sheet, ou un nom qui diverge entre deux tables (segment plus ancré sur aucun checkpoint jeu ⇒ plus de garde de départ ni de room de fin). `Tests/EndConditionTests.cs` : règles de dérivation `CategoryOf`/`EndConditionOf` (tolérance d'espacement incluse).
- `Tests/Fixtures/*.csv` — snapshots des deux onglets (2026-08-05, ~32 Ko). **Les rafraîchir est le mécanisme de détection** : re-télécharger les onglets et relancer les tests dit exactement quelles lignes la sheet a renommées ou supprimées. Ce ne sont volontairement pas des snapshots de valeurs (pas d'assertion sur les seuils, qui bougent tout le temps), seulement sur la structure.
- Les fichiers couplés au jeu (`SegmentSelector`, `TierComparison`, `RunWatcher`, hooks de `SegmentAutoDetect`, I/O de `SheetImporter`) ne sont pas testés unitairement : ils exigent `TextMenu`/`Dialog`/`GFX`/`Session`, les hooks MonoMod et l'interop SpeedrunTool, et leurs vrais bugs (timer qui se dé-complète, ordre capture/sélection) ne se révèlent qu'en jeu ⇒ checklist manuelle.

## Architecture

- `Source/SrsModule.cs` — `EverestModule` ; `Load()`/`Unload()` délèguent aux classes statiques ; `CreateModMenuSection` ajoute les entrées manuelles (bouton de mise à jour, plus tard les listes de sélection de segment — le menu auto-généré d'Everest ne sait pas faire de listes dynamiques).
- `Source/SrsSettings.cs` — settings Everest. `ASidesUrl`/`BSidesUrl` (`[SettingIgnore]` : pas dans le menu, éditables dans `Saves/modsettings-srs.celeste`) : URLs d'édition complètes des deux onglets importés, id/gid extraits par regex ; l'ancien `SheetUrl` (sheet prototype, pré-2.0.0) disparaît simplement au chargement (YamlHelper d'Everest ignore les clés inconnues). `SelectedChapter`/`SelectedCheckpoint` : sélection persistée par noms (le couple est nécessaire, les noms de checkpoints se répètent entre chapitres). `Category` (v3.0.0, enum `SegmentCategory`, défaut `AnyPercent`) : catégorie pratiquée, ne nourrit que l'auto-détection ; `CycleCategory` (v3.1.0, `ButtonBinding` non lié par défaut) la fait tourner en jeu, géré dans `SegmentAutoDetect`.
- `Source/SheetData.cs` — **pur, sans dépendance au jeu** (parseur testable) : parseur CSV RFC 4180 (guillemets, `""`, `\r\n`), parseur de temps `[hh:][mm:]ss[.fff]` (culture invariante), modèle `SheetData` → `SheetBlock` (une ligne d'en-tête = un bloc, détectée par `Hidden`+`WR` en colonnes 1-2 **ou** 2-3 → `TierStart` ; `HasCheckpoints` si la colonne 1 s'appelle `Checkpoint`) → `SheetSegment` (`Chapter` + `Name`, readonly ; le nom de chapitre n'est présent que sur la 1re ligne du groupe — cellules fusionnées — donc reporté sur les suivantes ; temps `TimeSpan?` alignés sur les colonnes depuis `TierStart`, null si cellule vide/illisible). Ne lève jamais d'exception sur contenu malformé. **`Parse(aSidesCsv, bSidesCsv)` (v2.0.0)** : parse brut des deux onglets (`ParseBlocks`, blocs sans colonne Checkpoint — « Chapter Times… » — ignorés) puis **filtre/renomme via la table `Import` hardcodée** (`(chapitre brut, checkpoint brut)` → `(chapitre mod, nom mod)`, whitelist — décision propriétaire 2026-08-05 : uniquement les checkpoints déjà supportés, pas de normalisation ; les variantes emoji 💙/📼/💎 et les lignes IL sont exclues, sauf `Depths 📼 RTM` → `Depths Tape` et `Hollows 📼 RTM` → `Hollows Tape`). Résultat : **un seul bloc fusionné** (segments dans l'ordre des lignes, onglet A puis B ⇒ les lignes B des chapitres pliés `5a/b`/`6a/b` suivent leurs lignes A comme sur l'ancienne sheet), colonnes reprises du premier onglet (les deux onglets partagent les mêmes). Adressage `(Chapter, Name)` inchangé partout ailleurs — seuls renommages visibles : `7a Start` → `0m`, ajout de `Depths Tape`. **v3.0.0** : chaque segment importé porte une `SegmentCategory` (`CategoryOf`, marqueur `📼` du nom brut → `Cassette`, `Contains` car l'espacement de la sheet est irrégulier — `📼 RTM`/`📼Clear` ; sans marqueur → `AnyPercent`) et une `EndCondition` (`EndConditionOf` : suffixe `Clear` → `ChapterComplete` même avec marqueur ; sinon `📼` → `Cassette`, `💙` → `Heart` — fin **à la collecte**, convention communautaire des lignes RTM ; sinon `Checkpoint` = prochaine room de checkpoint jeu, résolue au runtime). **v3.1.0** : `SegmentCategories` (même fichier, game-free) — `Names` (libellés sheet non traduits, indexés sur l'enum, source unique du slider **et** du popup du hotkey), `NameOf`, `Next` (cycle piloté par l'enum, pas par `Names`) ; `Tests/CategoryTests.cs` vérifie que la table couvre l'enum.
- `Source/SheetImporter.cs` — téléchargement des **deux onglets** (HttpClient statique, timeout 20 s, **async via `Task.Run`, jamais sur le thread de jeu, jamais au lancement** ; échec de l'un = échec de la mise à jour), détection sheet privée (réponse HTML au lieu de CSV), caches `Saves/srs/asides.csv` + `bsides.csv` (écriture atomique via `.tmp` + `File.Move`), rechargés dans `Load()` ⇒ hors-ligne OK (`CacheTime` = plus récent des deux fichiers ; l'ancien `sheet.csv` pré-2.0.0 est supprimé silencieusement). Les caches **sont** aussi le fallback manuel : des CSV déposés à la main y sont relus tels quels. Entrées de menu : bouton (label muté depuis le thread worker — sûr, les items relisent leur label chaque frame) + `SubHeader` de statut. Logs sous le tag `srs`.
- `Source/SegmentSelector.cs` — sélection du checkpoint à comparer (phase 4) : `Current` (résolu par `(SelectedChapter, SelectedCheckpoint)` dans `CheckpointBlock`, null si introuvable) ; deux `TextMenu.Slider` dépendants (changer de chapitre vide et re-remplit `Values` du slider checkpoint — liste mutable, pas de reconstruction du menu ; le menu est de toute façon reconstruit à chaque ouverture, donc les données fraîchement importées apparaissent à la réouverture). À l'ouverture, les settings sont resynchronisés sur ce qui est affiché (sélection périmée ⇒ redevient valide). **v3.0.0** : plus aucune écriture de `NumberOfRooms` (le réglage SpeedrunTool appartient de nouveau au joueur) — la sélection n'écrit que les settings. Slider **Catégorie** (`Any%`/`Cassette`, labels non traduits — vocabulaire de la sheet, indexés sur l'enum) au-dessus du toggle Auto ; il n'écrit que `Settings.Category`, l'auto-détection l'applique à la frame suivante — jamais grisé (sans effet en manuel, mais inoffensif).
- `Source/SegmentAutoDetect.cs` — phase 4bis : quand `AutoDetect` (défaut on), le checkpoint joué pilote la sélection. Chapitre depuis `Session.Area` (table `ChapterMap` : ID+Mode → chapitre sheet + côté des chapitres pliés), checkpoint = dernière room de checkpoint entrée (`Everest.Events.Level.OnEnter` initialise depuis `Session.StartCheckpoint`, null = « Start » ; `OnTransitionTo` + `LevelData.HasCheckpoint` met à jour), room → nom jeu via `CheckpointData` avec `Dialog.Clean` **forcé en anglais** (clés traduites), nom jeu → nom sheet via `CheckpointMap` **hardcodée, sans normalisation** (décision propriétaire 2026-07-18, reconduite en 2.0.0 ; `7a Start` → `0m`). La room trackée est enregistrée côté save states ; la sélection est réappliquée chaque frame (couvre les loads de savestate, sans callback). Chargé **en dernier** : son hook `Level.Update` doit rester le plus externe pour que la capture (`RunWatcher`) et le calcul de palier (`TierComparison`) d'une complétion précèdent le déplacement de sélection. **Suspendu tant que `RunWatcher.Completed`** : la complétion transitionne en général dans la room du checkpoint suivant, et déplacer la sélection re-pointerait la comparaison sur le mauvais segment et cacherait le résultat ; la room trackée continue de suivre, la détection rattrape au reset du timer (load de savestate, clear). `ChapterMap` est `internal` (ancrage des segments par `RunWatcher`), `GameNameOf`/`PlainNameOf` (Names.cs, game-free) inversent `CheckpointMap`+`CategoryVariants`. **v3.0.0 — résolution par catégorie** : `CheckpointMap` donne le nom « plain » ; la table `CategoryVariants` (`(Settings.Category, nom plain)` → variante, dans `SegmentAutoDetect.Names.cs`, game-free) le remplace par la variante de la catégorie active quand elle est importée (`Cassette` : `Depths` → `Depths Tape`, `Hollows` → `Hollows Tape`), repli sur la ligne plain sinon — les deux Tapes, qui partent du même checkpoint jeu que leur jumeau (rien d'observable ne les distingue à l'entrée), deviennent ainsi auto-détectables. La route 5A complète reste absente (non importée) — la sélection ne bouge pas. **v3.1.0** : le hotkey `CycleCategory` est traité en tête de ce hook (popup `ShowOptionState`, `SaveSettings`) — la catégorie ne sert qu'à la détection qui suit deux lignes plus bas, donc le changement s'applique dans la frame même.
- `Source/RunWatcher.cs` — **phase 6 (v3.0.0), remplace `RoomCounts`** : srs décide lui-même de la fin d'un run depuis l'`EndCondition` du segment sélectionné, SpeedrunTool n'est plus que le chronomètre (`GetRoomTime()` via ModInterop ; `NumberOfRooms` jamais touché, `RoomTimerIsCompleted()` plus utilisé). Hook `Level.Update` **le plus interne des trois** (chargé en premier après `SheetImporter`) : à `time == 0` (timer armé/reset) jette l'état du run ; au front 0→>0, `startRoom = Session.Level` **de cette frame-là** — c'est la room dont l'entrée a démarré le chrono (timer NextRoom armé une room avant le segment ⇒ démarre en transitionnant *dans* la première room du segment, `Session.Level` a déjà basculé ; CurrentRoom ⇒ la room du reset). Piège historique : prendre la room d'armement à la place (off-by-one, cassait le workflow savestate standard, corrigé 2026-08-06) ; ensuite évalue les conditions room-shaped (`Checkpoint` : `Session.Level` == room du checkpoint jeu suivant, résolue au runtime depuis `AreaData` — `EndRoomOf`, null ⇒ repli fin de chapitre, **et `endRoom != startRoom`** : un run ne finit jamais dans la room où son chrono a démarré — sur la frame du front 0→>0 la sélection peut encore être le segment précédent, dont la room de fin est exactement celle où l'on entre (complétion instantanée sinon, bug corrigé 2026-08-06 ; l'auto-détection bascule dans la même frame, après) ; `ChapterComplete` : `level.Completed`). `Cassette`/`Heart` : hooks `SaveData.RegisterCassette`/`HeartGem.RegisterAsCollected`, capture immédiate à la collecte. **Garde de départ** : `capturedTicks` gèle à chaque complétion, mais `hasCapture` (⇒ palier) seulement si `startRoom == ExpectedStartRoom` (ancrage du segment via `GameNameOf` — les variantes héritent de l'ancre de leur jumeau plain — « Start » = `MapData.StartLevel()`, ce qui impose le timer **CurrentRoom** pour les segments de début de chapitre : NextRoom ne peut pas chronométrer la première room) ; garde échouée ⇒ temps gelé affiché en gris sans palier (fin de run toujours visible). Garde-fou de chapitre : la session doit jouer le chapitre du segment (une cassette prise en 3A ne complète pas Hollows Tape). Les quatre champs (`startRoom`, `completed`, `hasCapture`, `capturedTicks`) sont enregistrés via l'interop `SpeedrunTool.SaveLoad`.
- `Source/TierComparison.cs` — phase 4 (remodelée par la 6) : hook `Level.Update` (après `orig`, enveloppe celui de `RunWatcher`) recalcule chaque frame la ligne depuis `RunWatcher.HasCapture`/`CapturedTicks` ; premier seuil ≥ temps ⇒ palier, au-delà de Red 3 ⇒ Unranked. **La ligne affiche le temps capturé à gauche du nom du palier, tous deux dans la couleur du palier** (format SpeedrunTool `s.fff`/`m:ss.fff`) — c'est le temps de référence du run, gelé à la vraie fin du segment, pendant que l'affichage SpeedrunTool suit son propre `NumberOfRooms`. Rendu après `orig` de `SpeedrunTimerDisplay.Render` (masqué si timer Off), décalé d'une ligne si srta est chargé ; couleurs = table hex `TierColors` indexée par nom de colonne complet (le suffixe de rang compte : `Purple 1/2/3` = 3 teintes distinctes ; WR/Hidden blanc, Unranked gris, inconnu → blanc). Hotkey `ToggleShowTier` (phase 5) gérée dans le même hook, popup on/off via `PopupMessageUtils` de SpeedrunTool (classe publique, pas de Publicizer). **Largeur du fond (v3.1.0)** : `60 + 18*(len-8)` — la formule de la ligne PB de SpeedrunTool, pas la largeur mesurée du texte. `strawberryCountBG` fait 288×38 et se dégrade vers la droite : toutes les lignes de la pile finissent **dans** le texte, la queue passant sur le fondu ; mesurer le texte plaçait tout le fondu *après* le dernier caractère (~433 px de large contre ~287 pour la ligne PB). Plus aucun état enregistré côté save states ici (la capture l'est dans `RunWatcher`).
- `Dialog/English.txt` + `French.txt` — `MODOPTIONS_SRS_TITLE` (titre du menu auto) et clés `SRS_*` (entrées manuelles). Pas de placeholders `{0}` dans les dialogs (Celeste peut interpréter les accolades) : composer en code.

## Repères SpeedrunTool (pour les phases 3-4)

- ModInterop `SpeedrunTool.RoomTimer` : `GetRoomTime()` (seul import restant depuis la phase 6 — `RoomTimerIsCompleted()` n'est plus utilisé, srs décide lui-même des fins de run) ; préférer l'interop au Publicizer (stable entre releases ; DemoJameson accepte des ajouts sur demande Discord).
- ModInterop `SpeedrunTool.SaveLoad` : tout état statique muté en gameplay doit y être enregistré (`RegisterStaticTypes`) sous peine de desync des save states.
- HUD : dessiner après `orig` de `On.Celeste.SpeedrunTimerDisplay.Render` (srs charge après SpeedrunTool ⇒ ses hooks enveloppent les siens) — voir `RoomDeltas.cs` de srta pour le modèle.

## Checklist « nouvelle fonctionnalité »

1. Créer `Source/<Feature>.cs` statique avec `Load()`/`Unload()`, appelés depuis `SrsModule`.
2. Option de menu → settings + clés dialog EN **et** FR ; entrées dynamiques dans `CreateModMenuSection`.
3. Réseau → uniquement à la demande explicite de l'utilisateur, timeout, erreurs loggées jamais levées.
4. État statique muté en gameplay → interop `SpeedrunTool.SaveLoad`.
5. Build, zipper `build/` en `srs.zip` dans `<Celeste>/Mods/` ; tester en jeu.
6. Si la logique est game-free (parsing, tables de noms, calculs), ajouter le test dans `Tests/` ; toucher à l'une des trois tables hardcodées ⇒ vérifier que `SheetConsistencyTests` passe encore.
7. Documenter dans le changelog du `README.md` (+ bump `Version` dans `everest.yaml` si release).

## Workflow git

Comme srta : branche `feature/<nom>` depuis `dev`, PR vers `dev`, release = merge dans `main` + bump de version mineure.
